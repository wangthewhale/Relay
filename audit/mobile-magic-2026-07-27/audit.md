# Relay Hero, Magic Moment, and Mobile UX Audit — 2026-07-27

Target states: Traditional Chinese landing page and read-only Mission demo at a 390 × 844 CSS-pixel viewport, with a 1440 × 900 desktop regression check.

## 1. Hero comprehension and hierarchy

- Before: the headline described a feature but did not communicate the category-defining outcome; five mobile lines, a second long headline, a long audience paragraph, and two CTAs delayed the proof.
- Change: rewrote the promise to “團隊給 AI 七個版本。Relay 只讓它執行安全的那一個。”; reduced the subhead to one input, one safety moment, and one consequence; removed secondary mobile CTA and body copy; preserved one primary action.
- Verdict: **Healthy.** The audience, problem, and outcome are understandable before the first scroll, and the primary CTA remains at least 44 px high.
- Evidence: `03-home-mobile-after.png`, `05-home-desktop-after.png`, `07-home-mobile-comparison.png`.

## 2. Landing-page Magic Moment

- Before: the compiler panel was a static illustration. It claimed an output but did not prove that Relay had run a compiler.
- Change: added a real, non-persisting `/api/preview-compile` path. The landing page now submits the brief, extracts assertions, detects conflicts, compiles governed tasks and scoped providers, shows the exact source evidence, pauses unsafe Agent tasks, and recommends the next safe action. Users can edit the source brief and run it again.
- Verification: replaced the sample with a different Taipei launch brief in the browser and confirmed the live compiler returned the date-versus-approval blocking conflict without navigating away or saving the preview.
- Verdict: **Healthy.** The visible result is generated by the same Relay compiler logic used for Missions, not a simulated animation.
- Evidence: `03-home-mobile-after.png`, `05-home-desktop-after.png`.

## 3. Mobile Mission demo

- Before: the desktop node graph remained fixed-width on mobile. The conflict, decision owner, Agents, and outcome sat offscreen; the command bar obscured content; a large empty area dominated the page.
- Change: mobile now uses a purpose-built vertical execution story: compiler receipt → conflicting evidence → blocked action → paused Agents → accountable human → recommended safe action. Desktop keeps the full canvas.
- Verification: confirmed all five conflict selectors work and switch the evidence, summary, owner, and resolution on a 390 px viewport.
- Verdict: **Healthy.** No horizontal dependency remains in the primary mobile journey, and the first viewport shows the product outcome instead of an empty canvas.
- Evidence: `04-demo-mobile-after.png`, `06-demo-desktop-after.png`, `08-demo-mobile-comparison.png`.

## 4. Responsive and desktop regression

- Landing page verified at 390 × 844 and 1440 × 900.
- Demo verified at 390 × 844 and 1440 × 900.
- Desktop React Flow nodes, evidence inspector, Agent states, and outcome node remain visible after the mobile-specific branch.
- Verdict: **Healthy.** Mobile and desktop now use the representation appropriate to each viewport without changing the underlying Mission data.

## 5. Accessibility and truthfulness limits

- Existing semantic headings, buttons, region labels, form labels, reduced-motion behavior, and 44 px primary touch targets are preserved.
- Preview copy explicitly states that it runs real compiler rules and does not save the text.
- Full assistive-technology and device-matrix certification was not performed in this pass; this audit verifies DOM semantics, keyboard-addressable controls, responsive layout, visible labels, and core interaction behavior.
- Verdict: **Good for this release; formal WCAG/device coverage remains a later QA track.**
